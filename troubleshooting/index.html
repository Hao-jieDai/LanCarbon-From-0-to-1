Troubleshooting Common Problems

Use the exact current message and the failed status card. Fix one cause, select Refresh Checks, and retry once.

GitHub CLI is installed but not detected¶

Restart LanCarbon after installation. Confirm gh --version works in a new terminal. If the terminal finds it but LanCarbon does not, reinstall GitHub CLI in its standard Windows location and restart the computer. Use the current LanCarbon release, which also checks the standard Program Files location.

Sign in appears to do nothing¶

Check the taskbar for the visible terminal. Complete the prompts there. If necessary, run gh auth login manually and then Refresh Checks.

Device authorization or OAuth token request times out¶

The browser approval may succeed while GitHub CLI cannot exchange the code for a token. Enable system/global proxy or TUN mode, start a new sign-in, and use the new one-time code. One-time codes expire; do not reuse the old code.

Failed to connect to github.com port 443, Connection was reset, or Recv failure¶

This is the Git HTTPS path. Enable a network mode that covers desktop programs, not only the browser. Refresh until Git HTTPS connection passes, then update. Do not reconnect the repository.

Repository exists, but setup reports 404¶

Check owner and repository spelling and confirm the signed-in account has administration access. A newly created repository or Pages configuration may need a short delay. Refresh and retry initialization. Use Existing repository for a repository already visible on GitHub.

Open Pages shows only an initial README or an old page¶

The repository may be initialized before the website deployment has completed. Compare the shown published commit, wait several minutes, and refresh the page without cache. Open Repository and inspect gh-pages. If no current website commit exists, run Update once after all checks pass.

“Site not loading correctly” or incorrect BASE_URL¶

The website must be built for its repository path, such as /My-Book/. Rebuild and republish with the current LanCarbon release and the correct repository binding. Do not reuse HTML manually copied from a different repository. If the error returns for a newly named Book, report the Book title and repository name because base-path handling must apply to every Book.

Update failed and the button is disabled¶

Read the card above it. An outdated Build requires Rebuild; missing authentication requires sign-in; a failed Git HTTPS check requires network recovery and Refresh Checks. The old public version remains available. The button should become available when real prerequisites pass.

Publication branch could not be downloaded¶

The detailed clone message usually reveals network failure, permission failure, or a missing branch/repository. Make the Git HTTPS check pass. Confirm the binding and account access. Retry; do not delete the local Book or published repository.

Build reports a deprecation warning¶

A dependency warning such as Node’s url.parse() deprecation may not be a Book error. Current LanCarbon filters known irrelevant warnings. Judge success by the error count, process result, and whether the website opens. Upgrade LanCarbon/Jupyter Book if a known warning persists.

Export says the target folder is not empty¶

Choose a new empty folder. Export deliberately avoids overwriting externally managed files. Build does not need this export.

Python, Jupyter Book, Git, or GitHub CLI is missing¶

Install the tool from its official source, restart LanCarbon, and reopen the relevant window. Build checks Python/Jupyter Book; Publish checks Git/GitHub CLI/account/network.

A public update still shows yesterday’s version¶

Confirm Update reported a newer commit and time. Wait for Pages, perform a hard refresh or private-window check, and open the repository to compare the branch commit. If no newer commit exists, the update did not complete and should be retried only after all checks pass.

When asking for help¶

Record the LanCarbon version, Book title, repository name, failed card, full error text, and whether system proxy/TUN mode was active. Do not share passwords, access tokens, or active one-time login codes.

常见问题处理¶

以当前实际错误文字和失败卡片为准。一次只修复一个原因，点击 Refresh Checks，然后重试一次。

已安装 GitHub CLI，但软件检测不到¶

安装后重启 LanCarbon。在新终端中确认 gh --version 可以运行。如果终端能找到但 LanCarbon 仍找不到，请把 GitHub CLI 重新安装到 Windows 标准位置，并重启电脑。使用当前版 LanCarbon，它也会检查标准 Program Files 位置。

点击 Sign in 看起来没有反应¶

检查任务栏中是否已经出现可见终端，并在其中完成提示。必要时手动运行 gh auth login，成功后回到软件 Refresh Checks。

设备认证或 OAuth token 请求超时¶

可能出现浏览器已经批准，但 GitHub CLI 无法用代码换取 token 的情况。开启系统/全局代理或 TUN 模式，重新开始一次登录，并使用新的一次性代码。旧代码会过期，不要重复使用。

Failed to connect to github.com port 443、Connection was reset 或 Recv failure¶

这是 Git HTTPS 连接问题。开启能够覆盖桌面程序的网络模式，而不只是浏览器代理。刷新检查，直到 Git HTTPS connection 通过，再更新。无需重新绑定仓库。

GitHub 上已有仓库，但初始化报告 404¶

核对 owner 与 repository 拼写，并确认当前登录账号具有管理权限。新仓库或 Pages 配置可能需要短暂等待。刷新后重试初始化。对已经在 GitHub 中可见的仓库，应选择 Existing repository。

Open Pages 只显示初始 README 或旧页面¶

仓库可能已经初始化，但网站部署尚未完成。对照 Published website 的 commit，等待几分钟后进行无缓存刷新。用 Open Repository 检查 gh-pages。如果没有当前网站 commit，在全部检查通过后执行一次 Update。

出现“Site not loading correctly”或 BASE_URL 错误¶

网站必须针对仓库路径构建，例如 /My-Book/。使用当前 LanCarbon 版本和正确仓库绑定重新 Build、Publish。不要手工复制其他仓库生成的 HTML。如果新书名仍出现此问题，请同时记录 Book title 与 repository name，因为基础路径处理必须对每本 Book 生效。

Update 失败后按钮变灰¶

阅读按钮上方的状态卡。Build outdated 时先 Rebuild；认证缺失时重新登录；Git HTTPS 检查失败时先恢复网络并 Refresh Checks。旧在线版本仍会保留。真实前置条件通过后，按钮应重新可用。

无法下载 publication branch¶

详细 clone 信息通常会指出网络失败、权限不足或分支/仓库不存在。先让 Git HTTPS 检查通过，再确认绑定与账号权限。然后重试；不要删除本地 Book 或线上仓库。

Build 显示 deprecation warning¶

例如 Node url.parse() 的依赖提示可能不是 Book 错误。当前 LanCarbon 会过滤已知无关提示。请根据 error 数量、进程结果以及网站能否打开判断。已知 warning 持续出现时，更新 LanCarbon/Jupyter Book。

Export 提示目标目录不是空文件夹¶

选择一个新的空文件夹。Export 为了保护外部文件而不会覆盖非空目录。Build 不需要这份 export。

缺少 Python、Jupyter Book、Git 或 GitHub CLI¶

从官方来源安装，重启 LanCarbon，再打开相关窗口。Build 检查 Python/Jupyter Book；Publish 检查 Git/GitHub CLI/账号/网络。

在线仍显示昨天的版本¶

确认 Update 是否显示了更新的 commit 与时间。等待 Pages，使用强制刷新或隐私窗口检查，并打开仓库比较分支 commit。如果没有新 commit，说明更新没有完成；应在全部检查通过后再试。

寻求帮助时¶

请记录 LanCarbon 版本、Book title、repository name、失败卡片、完整错误文本，以及系统代理/TUN 模式是否开启。不要分享密码、access token 或仍有效的一次性登录代码。
